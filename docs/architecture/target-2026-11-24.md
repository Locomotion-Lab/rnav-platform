# 云端单节点与双域名方案（2026-11-24）

平台运行在现有腾讯云服务器上，用两个域名区分公开官网和内部控制台。保留 Monorepo、独立的 Next.js 和 Express 进程，以及共同的 PostgreSQL 和现有 COS。Mac 只用于开发和测试。此方案替代此前的云端与 Mac 双节点迁移方案。

| 入口 | 职责 |
| --- | --- |
| `https://r-navigation.com` | 公开展示课题组、研究方向、成员、论文、实验平台、新闻和联系方式。 |
| `https://console.r-navigation.com` | 登录后进入对外展示信息管理、成员与账号管理、设备管理。后续增加小砺智能体和云服务器远程使用。 |

Nginx 按域名路由。初期两个入口可以共用一个 Next.js 部署，内部页面和业务 API 按域名与权限限制访问。旧官网的 `/console` 入口和已知页面链接定向到新控制台；管理员入口及后续小砺入口以控制台域名为准。控制台通过同源 API 访问 Express，登录 Cookie 仅属于控制台主机。官网提供公开页面、公开数据及公开媒体。Express 和 PostgreSQL 仅供服务器内部访问。

## 数据如何互通

- **成员与账号**：继续使用同一套账号、成员资料和权限模型。官网成员页从成员资料的公开状态和允许公开的字段生成，控制台可以预览、发布和撤下。账号停用与公开资料撤下分别管理，以便保留获准公开的校友资料。
- **设备**：控制台维护设备和实验平台，一份记录可带有选择公开的展示资料。官网只显示公开的设备、平台资料及规格。设备编号、序列号、存放位置和内部维护记录留在控制台。
- **对外展示信息**：在控制台集中管理页面内容、新闻、媒体、成员展示和论文。优先复用现有公开投影和发布能力。发布后官网读取同机的公开版本，保留上一个版本以便回退；已有媒体继续使用 COS，公开页面只引用获准公开的媒体。两域名共享一套业务数据，公开版本只是其展示副本。

## 论文展示

1. **先确定老师的论文。** 在展示管理中集中维护纳入同步的老师及其来源，可沿用已有的 OpenAlex 作者标识，也可人工添加有明确出处的论文。来源配置由管理员维护。成员个人资料页和普通成员工作流移除学术身份绑定和个人论文同步入口，已存身份及成果历史保留。
2. **审核后公开。** 系统把老师论文作为候选，管理员核实归属后发布。优先沿用 DOI 或来源的论文 ID 去重。同一篇论文有多位老师或成员时只生成一条展示记录。对已有公开论文做一次归属复核，无法确认的留待审核，并在发布新版本前核对拟撤下的条目。
3. **再匹配作者。** 用论文的作者顺序、姓名和成员资料中已有的中英文姓名或曾用名生成建议。现有已核验的作者关系可作为证据。同名、英文缩写或拼音冲突由管理员确认，管理员可补配、修正或取消关联。成员姓名匹配只影响高亮，论文能否公开由老师归属和发布状态决定。
4. **公开页面保留原始作者顺序。** 只高亮已确认且获准公开展示的成员，提供公开成员页时链接到该页面。其余作者按论文原样展示；作者匹配过程及内部账号标识留在控制台。

首版以老师来源维护、候选审核、作者关联和发布为主。沿用现有论文、来源和作者关系的数据结构，逐步收起成员侧身份绑定、同步设置及相关任务入口。

## 内部功能与实施顺序

| 优先级 | 功能 | 首版范围 |
| --- | --- | --- |
| 现在 | 对外展示信息管理 | 官网内容和媒体、公开成员及实验平台、老师论文与作者高亮、预览和发布。 |
| 现在 | 成员与账号管理 | 账号、角色权限、成员资料、公开字段及可见性。 |
| 现在 | 设备管理 | 台账、设备资料、内部维护、实验平台与选择性公开。 |
| 后续 | 小砺智能体 | 作为控制台的登录后入口，随用户权限调用现有业务 API。 |
| 后续 | 云服务器远程使用 | 作为控制台的登录后入口，独立授权，并与官网和业务 API 的运行进程分开。具体使用方式与账号范围在该功能立项时确定。 |

采购与设备实时监控继续从活动产品中移除，包括导航、页面、API 和后台任务。现有开发分支已完成主要移除工作，下一版上线前验证生产切换涉及的旧入口和任务。历史表、文件和现有引用关系保留。

1. **先实现双域名和三项核心功能。** 基于现有 Web、后端和数据模型做路由、会话及控制台导航调整。验证官网和控制台的访问边界，以及成员、账号、设备和已有公开页面的回归。
2. **再替换论文流程。** 加入老师来源与候选审核，保留和复用历史数据，验证同名、重名、隐藏成员、多人合著和去重，再用预览核对已有论文变更。
3. **最后完成云上发布验证。** 新版先在云端候选入口验证，继续使用同一套云端业务数据，沿用现有数据库和文件备份能力。生产切换前核对两个域名的 DNS/TLS、会话与公开范围，准备 Nginx 和应用版本回滚。云端部署及正式切换另行审批。旧双节点 Runbook 停用。
4. **核心功能稳定后再开发小砺和远程使用。** 两项功能复用账号和权限体系，各自按实际使用需求设计。
