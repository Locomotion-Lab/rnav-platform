# 成员目录、角色与媒体更新

本次改造沿用腾讯云上的 Web、API、PostgreSQL 和 COS。谁能维护平台、成员在组里是什么身份、有哪些学位、是否在校，分别存储和维护。

| 维度 | 管理方式 |
| --- | --- |
| 权限身份 | 成员、管理员。管理员拥有完整维护权限。任一管理员可以调整任一账号角色。角色变更会撤销该账号的旧会话。最后一个启用的管理员受保护。 |
| 在组身份 | 老师、学生。老师按老师分组，学生按主学位分组。 |
| 学位身份 | 博士、硕士、本科，可多选，主学位依次以博士、硕士、本科为先。未取得硕士学位的硕转博成员只选博士。原记录缺学位时允许后续补填。 |
| 在校状态 | 在校、校友，可独立修改。旧的「转为校友」复合操作已合并到资料编辑。 |

普通成员在控制台浏览卡片，点开查看已填资料。账号邮箱、安全状态、角色变更和发布设置属于管理功能。公开官网沿用成员的公开字段选择。新版快照会在成员详情显示已选择公开的多个学位。

## 数据升级

- 047 将原博士、硕士、本科映射为学生与相应学位，原教师映射为老师，原博士后映射为老师与博士。历史数据里没有的学位不推断。保留原字段供旧程序和历史工具读取。
- 生产只读核对发现待核对的硕转博成员已经是博士记录，现有数据转换后只保留博士。原博士后记录会映射到老师与博士。
- 生产只读核对确认启用的系统账号为 `@admin` 和四个旧账号。047 停用旧系统账号及其会话，历史记录和外键继续保留。原有人员管理员继续保留其角色。旧细粒度权限分配保留作历史查询。
- 048 根据当前引用为原媒体分类，新上传头像使用 `avatar/<资源 ID>/<用户名>.<扩展名>`。同一成员多次上传时，新旧图片地址独立。官网、设备与其他媒体使用各自目录。
- 保存替换或移除图片后，只有引用数归零的原图片进入回收站。历史成员、采购目录、存储迁移日志及旧 URL 引用也计入引用。已发布快照保有独立文件。回收期三天，可在媒体库恢复。定时器每天北京时间 04:30 复核引用并永久删除到期的自动回收图片。已有回收记录和手动回收项仍由管理员处理。

## 验证

`npx tsx scripts/ops/smoke-member-directory.ts` 创建独立的临时 PostgreSQL 14 容器，从 046 合成数据升级，使用真实 HTTP、数据库和本地文件存储演练。结束后清除该容器和演练数据。覆盖旧系统会话失效、历史权限不再授予管理员访问、双学位、老师博士、匿名与普通成员权限、跨账号头像访问、共享引用、回收、历史引用和快照媒体留存。

Chrome 验收使用 390px 和 1440px 页面，覆盖目录分组、成员详情、头像读取、管理员勾选学位后保存及两种账号角色。生产只读检查确认仍在 `fc3544b`。实际生产 COS 对象删除留到授权后的验证窗口。

## 生产发布待确认

1. 在维护窗口记录当前发布目录、活动快照和账号角色分布。使用生产备份流程生成可恢复的 PostgreSQL 备份，在隔离库核验 047–048。记录旧系统账号的用途，确认运行任务不再依赖其登录凭证。
2. 在腾讯云候选版本执行 `npm ci`、`npm run api:check`、`npm run build`。冻结业务写入后，由有 DDL 权限的迁移账号注入 `DATABASE_URL` 并运行 `npm run db:migrate`。核验旧系统账号和会话、人员角色数、新身份计数后，切换 `/srv/rnav/current` 到候选版本并重启 `rnav-backend`、`rnav-web`。
3. 用现有成员和管理员会话复核两种账号的目录、详情、编辑及设备流程。用控制台审核并发布新快照，复核官网展示，保留上一版本供回退。
4. 确认允许自动删除符合条件的 COS 图片后，安装 `deploy/systemd/rnav-media-cleanup.{service,timer}`，执行 `systemctl daemon-reload` 和 `systemctl enable --now rnav-media-cleanup.timer`。用 `systemctl list-timers rnav-media-cleanup.timer` 与 `journalctl -u rnav-media-cleanup.service` 核验运行。

遇到回归先停用媒体清理 timer，并按现有云端流程恢复上一份应用和活动快照。保留新版列、历史账号和切换后的写入。回退到旧应用时，旧权限分配会重新参与授权，恢复写入前需核对管理权限。已删除的原始对象需从存储备份恢复。备份用于隔离核验和定点恢复，避免覆盖切换后的业务写入。
